# Shodo arm laboratory

Use Python 3.13 with uv. Makefile is the command entry point. Keep all work in this directory; the parent is an unrelated multi-project repository. Never commit downloaded data, virtual environments, or bulky training runs. Preserve source attribution in derived datasets. Run `make check` and `make validate` after simulation changes.

Architecture: pinned KanjiVG SVGs -> pressure/tilt/contact trajectories -> Gymnasium environment -> torque-driven pinned B601-RS -> coupled brush -> conservative ink grid. The fast brush uses elastic/frictional bundles; optional native rods use MuJoCo's cable plugin. Six action slots retain XYZ increments and suppress rotation requests for a rigid vertical brush. Damped IK feeds bounded MIT joint impedance. See PHYSICS.md for equations, source attribution and limits. Never teleport outside reset.

Default train characters: 一二三十木大人. Held-out characters: 永水日山. Never claim calligraphy mastery or sim-to-real readiness from trajectory tracking. Validation must compare teacher, learned, and zero-action baselines on held-out paths, check physical tracking and pen lifts, and render actual executed motion. Online research may be delegated as requested by the user. Prefer official primary sources and document limitations. Keep tests focused on integration and invariants.

Current validation and known approximations are recorded in VALIDATION.md. Canonical outputs use `runs/validation-rollout.*`. Training seeds/settings, package versions and source hashes are saved with artifacts. Avoid opening a GUI: default operation and rendering must remain headless.

Preserve the privileged 40-input checkpoint contract 3 separately from `sensor-history` contract 1 (39 features per history slice). Sensor actors must not receive contact-center, bristle-deflection, contact-fraction or ink-state truth; privileged teacher labels/rewards and separately named diagnostics are permitted. Sensor force is a synthetic compensated contact-force proxy, not a calibrated wrist sensor. Use `contracts.py` for action/observation semantics and `runtime.py` for sensor adaptation/execution. Learned checkpoints must reject mismatched modes/history; corruption overrides are evaluation settings, not silent resume changes.

Training datasets use `dataset.py`, not presentation MP4s. Preserve transition alignment, acquisition/decision time distinctions, requested versus effective clipped command increments, and separate privileged columns. Raw camera frames must have no diagnostic overlays or paper inset. Dataset publication refuses overwrites. Robustness uses paired seeds and explicit registration/calibration/noise/delay/dropout cases; estimated paper-frame errors do not physically move the paper. Keep failures and valid denominators in reports; sensor evaluation is not hardware qualification.

Recordings use FFmpeg/libx264 MP4 with simulation-aligned timing. Keep terminal output concise and human-readable; save full arrays and provenance in JSON/NPZ, and print artifact paths. FFmpeg is required for demo/validation recording, not numerical training/evaluation.

Neural training and inference default to CPU because measured small-policy workloads on this host are slower on Apple Metal. `--device auto` (`DEVICE=auto` in Makefile) opts into CUDA, then Apple Metal, then CPU according to availability; explicit backends are also supported. Dynamics and ink transport remain on CPU. Record the resolved device and verify checkpoint portability; choose optimizations from measurements, not accelerator availability alone.

SmolVLA is an optional integration with a separately tracked lockfile in `integrations/smolvla`; do not add its constrained LeRobot/PEFT stack to core dependencies. Its explicit workflow uses `VLA_DEVICE=auto`. Keep pretrained model revisions pinned, base weights frozen during LoRA training, causal raw-camera selection, shared training/inference normalization, adapter integrity checks, and held-out character separation. Training-minibatch loss and synchronous simulation latency are not policy qualification or real-time deployment evidence. Never upload recordings or adapters automatically.

Recovery recordings preserve actual requested/applied behavior actions separately from pre-action counterfactual expert labels. Expert supervision is training-only and requires one-action chunks: successive labels along noisy behavior do not describe a coherent future expert rollout. Preserve normalization semantics embedded in each artifact. Cache only immutable acquired-frame image/language input embeddings, never the current state projection or state-dependent processed VLM prefix; invalidate on frame/task changes and clear caches on reset. LoRA merging can change floating-point actions and must be checked separately from exact cache reuse. Measure fresh-frame and held-frame end-to-end latency, not only neural kernel time, and distinguish execution-horizon throughput from the 20 ms control deadline.

VALIDATION.md separates the fixed comparison from exploratory controller extensions and documents remaining physical limitations. WORK_LOG.md is a concise engineering summary, not a chronological transcript. Use `runs/` with descriptive experiment subdirectories; rely on git for source history and remove obsolete outputs instead of maintaining versioned trees. Checkpoint observation contract is 3 and includes brush contact offset. Native cable checks include beam response, mass, recovery, penetration, force and timestep/geometric sensitivity; absence of solver warnings alone remains insufficient evidence of physical accuracy. Keep prose paragraphs unwrapped; preserve intentional line breaks in code, tables and lists.

B601-RS uses six physical joint slots plus a reserved zero seventh slot in both observation layouts. Require the separate robot contract and vertical action contract 2; never reinterpret Panda checkpoints or expose a native rod coordinate through the reserved slot. Run `make prepare` for changed robot placement, tool attachment or actuation settings. `DEPLOYMENT.md` records public-source uncertainties and the unimplemented hardware boundary. Report actual actuator_force, not affine actuator ctrl inputs, as motor torque.

Keep the full pytest suite below 300 tests and target at most 5 seconds on this host. Prefer short physical boundary fixtures and distinct failure/invariant coverage over argument permutations or repeated full-glyph runs; keep long controller and refinement studies in their explicit Make targets. Measure the entire suite without competing experiment jobs and do not meet the budget by silently deselecting tests.
